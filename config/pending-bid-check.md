# بررسی ثبت پیشنهاد — Pending Bid Check

**هدف:** جلوگیری از فراموشی ثبت «پیشنهاد دادم» در `bids-log` بعد از ارسال واقعی در پونیشا.

**این فایل workflow ثبت است — نه Proposal Engine و نه Negotiation Engine.**

---

## فایل‌های مرتبط

| فایل | نقش |
|------|-----|
| `config/last-proposal.md` | آخرین Proposal تولیدشده توسط agent (منبع حقیقت برای چک) |
| `config/bids-log.md` | ثبت نهایی پس از «پیشنهاد دادم» |
| `config/proposal-learning.md` | ردیف اولیه یادگیری (همان قانون قبلی) |
| `config/project-status.md` | وضعیت‌های Submitted / Negotiation / Won / Lost |

---

## تریگر

| عبارت کاربر | عمل |
|-------------|-----|
| **«پونیشا»** / **«بعدی»** | **اول** Pending Bid Check — **بعد** (در صورت OK) جستجو + Proposal جدید |
| **«پیشنهاد دادم»** | ثبت در `bids-log` + `proposal-learning` + به‌روز `last-proposal` → Submitted |
| **«هنوز ارسال نکردم»** | `bids-log` بدون تغییر؛ اگر Ready بود → **Ready بماند**؛ ادامه به پروژه جدید **فقط با تأیید صریح** کاربر |

---

## Ready ≠ ارسال‌شده

**Ready** یعنی «آماده ارسال در پونیشا» — **نه** «حتماً ارسال شده».

agent **نباید** Ready را به‌عنوان Submitted فرض کند. فقط بپرسد کاربر ارسال کرده یا نه.

---

## الگوریتم (اجباری — قبل از پروژه جدید)

```
۱. config/last-proposal.md را بخوان
۲. اگر خالی است یا «بدون Proposal فعال» → ادامه به پروژه جدید
۳. ID پروژه last-proposal را در bids-log جستجو کن

─── اگر ID در bids-log است ───
۴. وضعیت last-proposal را با bids-log هم‌خوان کن → ادامه

─── اگر ID در bids-log نیست ───
۵. اگر وضعیت = Ready (یا Draft):
     → فقط بپرس: «ارسال کردید؟» (پیام زیر)
     → پروژه جدید **فعلاً** نساز — منتظر پاسخ

۶. پاسخ «پیشنهاد دادم» → ثبت Submitted → سپس می‌توان پروژه جدید داد

۷. پاسخ «هنوز ارسال نکردم»:
     → Ready (یا Draft) **بدون تغییر**
     → بگو: «می‌خواهید به پروژه بعدی برویم؟» — ادامه **فقط** اگر کاربر تأیید صریح داد
       (مثلاً «ادامه»، «بله بعدی»، «پروژه جدید بده»، «ردش کن برو بعدی»)
     → بدون تأیید → همان Proposal Ready بماند؛ پروژه جدید نساز
```

---

## پیام چک (Ready / Draft — هنوز در bids-log نیست)

> پیشنهاد **[ID] — [عنوان]** در وضعیت **Ready** است (آماده ارسال — نه لزوماً ارسال‌شده). در پونیشا submit کردید؟
>
> - **«پیشنهاد دادم»** → ثبت Submitted در bids-log
> - **«هنوز ارسال نکردم»** → Ready می‌ماند؛ برای پروژه بعدی **تأیید** بدهید

خلاصه: ID، عنوان، مبلغ، زمان.

---

## وضعیت‌های last-proposal

| وضعیت | معنی |
|--------|------|
| **Draft** | پیش‌نویس تولید شد؛ Human Review نشده یا ناقص — **ارسال نشده** |
| **Ready** | نسخه آماده paste در پونیشا — **ارسال نشده تا کاربر بگوید «پیشنهاد دادم»** |
| **Submitted** | کاربر تأیید کرد + در `bids-log` ثبت شده |
| **Negotiation** | هم‌خوان با `bids-log` / `project-status` |
| **Won** / **Lost** | هم‌خوان با `bids-log` / `project-status` |

---

## بعد از تولید Proposal جدید

agent **باید** `config/last-proposal.md` را به‌روز کند:

- ID، عنوان، مبلغ، زمان تحویل، متن بلوک ۱
- تاریخ تولید (شمسی)
- وضعیت: **Draft** (پیش‌نویس) یا **Ready** (پس از Human Review / تأیید کاربر)

---

## ثبت با «پیشنهاد دادم»

### ۱. `bids-log.md`

ردیف جدول:

| تاریخ | ID | عنوان | مبلغ | زمان | وضعیت |

- تاریخ = امروز (شمسی) مگر کاربر تاریخ دیگری بگوید
- وضعیت = **Submitted**

بخش **متن Proposal** (زیر جدول یا در `## جزئیات Proposalها`):

```markdown
### [ID] — [عنوان]

| فیلد | مقدار |
|------|--------|
| تاریخ ثبت | … |
| مبلغ | … |
| زمان تحویل | … روز |
| وضعیت | Submitted |

**متن ارسال‌شده:**

\`\`\`text
[بلوک ۱ — متن چت پونیشا]
\`\`\`
```

### ۲. `proposal-learning.md`

ردیف اولیه (همان قانون قبلی «پیشنهاد دادم»).

### ۳. `last-proposal.md`

- وضعیت → **Submitted**
- `در bids-log` → **بله**
- `تاریخ ثبت bids-log` → تاریخ ثبت

### ۴. System Metrics

+۱ Proposal در `proposal-learning.md` (پس از Freeze).

---

## «هنوز ارسال نکردم»

- `bids-log` — **بدون تغییر**
- `last-proposal` — **Ready** (یا Draft) **بدون تغییر**
- **پروژه جدید در همان نوبت شروع نشود**
- برای ادامه بدون ثبت: از کاربر **تأیید صریح** بگیر — مثلاً «ادامه»، «بله بعدی»، «پروژه جدید»، «ردش کن»
- پس از تأیید → می‌توان پروژه جدید داد؛ last-proposal Ready **می‌تواند** بماند (تا کاربر بعداً «پیشنهاد دادم» بگوید یا Proposal جدید جایگزین شود)

---

## استثنا

اگر `last-proposal` مربوط به پروژه‌ای است که در **رد شده (پیشنهاد نده)** یا **Lost** است → چک را رد کن و last-proposal را پاک/آرشیو کن.

---

## commit

بعد از ثبت «پیشنهاد دادم» یا به‌روزرسانی معنادار `last-proposal` → commit با پیام مثل: `bids-log: #749426 Submitted`

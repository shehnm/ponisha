# Proposal Intent Control — کنترل Intent پیش از تولید

**هدف:** قبل از نوشتن Proposal (یا پاسخ مذاکره) مشخص شود این پیام در **کدام مرحله Funnel** است و **هدف اصلی** آن چیست — سپس محتوا بر همان اساس **محدود** شود.

**محدوده:** فقط **لایه تصمیم Intent** — **Proposal Engine و Negotiation Engine بدون تغییر.**

| موتور | وظیفه | این فایل |
|--------|--------|----------|
| **Proposal Engine** | Risk + Insight + Simulation → بلوک ۱ | ❌ تغییر نمی‌کند — **Intent را رعایت می‌کند** |
| **Negotiation Engine** | Pipeline پاسخ مذاکره (#21) | ❌ تغییر نمی‌کند — Stage ۲/۳ |
| **Proposal Intent Control** | مرحله Funnel + هدف پیام + سقف اطلاعات | ✅ تصمیم قبل از نوشتن |

**ارتباط:**
- `negotiation-conversion-analysis.md` — Funnel پس از Submit (Proposal دیده شد → … → Won/Lost)
- `emotional-trust-layer-analysis.md` — AAL قبل نوشتن؛ PCL قبل HR (فشرده‌سازی Stage ۱)
- `proposal-generation-logic-analysis.md` — ثبت «چرا این Intent»
- `human-review-loop.md` — تأیید Intent قبل HR

---

## قانون اصلی

**Proposal اولیه نباید تبدیل به توضیح کامل پروژه شود.**

| نوع اطلاعات | کجا |
|-------------|-----|
| **جلب اعتماد اولیه** — فهم مسئله، یک Risk، یک قدم/سؤال | **Stage ۱ — Proposal** |
| **تصمیم همکاری** — Scope کامل، قیمت/زمان جزئی، شرایط، بستن | **Stage ۳ — Negotiation** |
| **شروع گفتگو** — پاسخ دغدغه، قدم بعدی، **بدون Scope کامل** | **Stage ۲** |

**مدیریت Intent = مدیریت حجم و نوع اطلاعات** — نه تغییر Engine.

---

## مراحل Funnel — Intent

### Stage 1 — Initial Proposal

**تریگر:** «پونیشا» / «بعدی» → اولین bid؛ **بلوک ۱** پیشنهاد اولیه.

| | |
|--|--|
| **هدف** | جلب توجه + **اعتماد اولیه** — کارفرما بخواند و **دلیل پاسخ** پیدا کند |
| **نه** | فروش/بستن کامل پروژه؛ توضیح Scope کامل؛ اثبات همه توانایی‌ها |

**قوانین:**

- هدف **فروش کامل** پروژه **نیست**
- فقط اطلاعات **لازم برای اعتماد اولیه**
- توضیحات اضافه → **نگه دار برای مذاکره** (Stage ۲/۳)
- یک Risk + یک Insight (یا بدون) + سؤال/قدم بعدی — **کافی**
- هم‌راستا با `PCL` سطح ۱ و `AAL` Trust Trigger

**سقف محتوا (راهنما):**

| مجاز در Stage ۱ | ممنوع / به مذاکره موکول |
|-----------------|-------------------------|
| فهم brief + یک نگرانی | لیست کامل مراحل اجرا |
| یک روش/اقدام مشخص | جزئیات قیمت/زمان در متن |
| یک Risk + راه‌حل کوتاه | پشتیبانی/گارانتی/SLA (#15) |
| سؤال هوشمند یا قدم بعدی | Scope line-by-line |
| «مبلغ و زمان در فرم» ([Keep]) | اثبات همه مهارت‌ها |

---

### Stage 2 — Conversation Start

**تریگر:** کارفرما **اولین بار** پاسخ داد؛ هدف پاسخ = **شروع/ادامه گفتگو** (نه بستن).

| | |
|--|--|
| **هدف** | **گرفتن پاسخ** — گفتگو را زنده نگه دار |
| **نه** | Scope کامل؛ قرارداد؛ همه جزئیات فنی |

**قوانین:**

- **سؤال** یا **قدم بعدی مشخص** (#20)
- **دغدغه اصلی** کارفرما در این پیام پاسخ داده شود
- هنوز **Scope کامل** لازم **نیست**
- Pipeline: **Negotiation Engine** — Intent Control فقط **Stage = ۲** را اعلام می‌کند

---

### Stage 3 — Negotiation

**تریگر:** گفتگو به scope/قیمت/زمان/بستن رسید؛ یا هدف پاسخ = مذاکره/بستن (#21).

| | |
|--|--|
| **هدف** | رفع نگرانی، شفاف‌سازی Scope، قیمت، زمان، **بستن قرارداد** |
| **مجاز** | جزئیات بیشتر — بر اساس **نگرانی واقعی** کارفرما |

**قوانین:**

- پاسخ متناسب با **هدف تشخیص‌داده‌شده** Negotiation Engine
- Intent Control **Stage = ۳** — سقف اطلاعات بالاتر از Stage ۱
- `#15` `#16` همچنان معتبر

## تشخیص Stage — قبل از نوشتن

**اجباری** — قبل از بلوک ۱ (Proposal) یا قبل از پاسخ مذاکره:

```markdown
| فیلد | مقدار |
|------|--------|
| ID | |
| **Stage** | ۱ Initial / ۲ Conversation / ۳ Negotiation |
| **هدف اصلی این پیام** | (یک جمله) |
| **چه چیز عمداً نمی‌نویسم** | (Scope کامل / …) |
| **چه چیز باید در متن باشد** | (حداکثر ۳ bullet) |
```

| وضعیت | Stage پیش‌فرض |
|--------|----------------|
| پیشنهاد اولیه جدید | **۱** |
| اولین پاسخ کارفرما — سؤال/سلام | **۲** |
| بحث scope/قیمت/زمان/نمونه/بستن | **۳** |

**قانون:** اگر Stage **۱** است → Engine همان Risk+Insight+Simulation — اما **Intent** محدودکننده حجم و نوع خروجی است.

## بررسی قبل از Human Review (Stage ۱)

**فقط برای Proposal اولیه (Stage ۱)** — بعد از پیش‌نویس، **قبل** Human Review:

### Over-Proofing Test

```markdown
| سؤال | پاسخ |
|------|------|
| آیا Proposal **بیش از حد** تلاش کرده **همه چیز را ثابت** کند؟ | بله / خیر |
| آیا Scope/روش **کامل** توضیح داده شده؟ | بله → **زیاد** برای Stage ۱ |
| آیا **بیش از یک** Risk یا Insight فشرده نشده آمده؟ | بله → فشرده کن |
| **اقدام** | اگر over-proofing = بله → **کوتاه‌تر** با PCL — **اعتماد حفظ** |
```

**آستانه:**

| نتیجه | اقدام |
|--------|--------|
| Over-proofing = **بله** | PCL-۱/۲ — حذف سطح ۳ و بخشی از سطح ۲؛ **سطح ۱** حفظ |
| Stage ۱ ولی شبیه Stage ۳ | **بازنویسی** — جزئیات به مذاکره موکول |

> **تفاوت با PCL:** Compression = حذف بی‌ضرر — Over-Proofing = **Intent اشتباه** (نوشتن برای Stage ۳ در Stage ۱)

## ترتیب Pipeline

```
Selection + feasibility
  → **Proposal Intent Control** — Stage + هدف + سقف اطلاعات   ← قبل از نوشتن
  → AAL (Client Type, Language, Trust Trigger)
  → Proposal Engine → بلوک ۱
  → Emotional Trust + CPS + PBA + AAL-۴ + PCL
  → **Over-Proofing Test** (اگر Stage ۱)
  → Human Review
```

**مذاکره:**

```
پیام کارفرما → Intent: Stage ۲ یا ۳
  → Negotiation Engine (بدون تغییر)
  → Conversion Analysis
```

# تریگر «پونیشا» — وقتی کاربر فقط یک کلمه گفت

**این فایل مهم‌ترین منبع برای Session جدید است.**  
اگر کاربر گفت **«پونیشا»** یا **«بعدی»** (بدون متن آگهی، بدون اسکرین، بدون لینک) → **همین فایل را اجرا کن.**

---

## «پونیشا» یعنی چه؟

**پونیشا** = سایت فریلنس ایرانی `ponisha.ir` — کاربر با Cursor + AI روی پروژه‌های آنجا bid می‌زند.  
این ریپو (`shehnm/ponisha`) حافظه، قوانین، لاگ bid و workflow پیشنهادنویسی است — **نه** کد سایت پونیشا.

**«پونیشا» / «بعدی» بدون context اضافه** = کاربر می‌خواهد Agent **خودش** پروژه بعدی را پیدا کند و پیشنهاد بدهد.

---

## ممنوع — هرگز این کار را نکن

| ❌ ممنوع | ✅ درست |
|---------|---------|
| «متن آگهی پروژه را بفرست» | خودت پروژه را از پونیشا پیدا کن |
| «بودجه و اسکرین رقبا را بفرست» | بودجه را از صفحه پروژه بخوان؛ رقابت از صفحه یا اسکرین بعداً |
| merge branch / git بدون درخواست کاربر | فقط فایل‌های config این ریپو را بخوان |
| web-fetch تصادفی بدون برنامه | fetch فقط صفحات پروژه/جستجوی پونیشا |
| اولین hit جستجو = پیشنهاد | چند کاندید؛ Fit اول، بعد Freshness |
| تکیه به JSON/API بدون HTML | HTML صفحه را برای «انتخاب کرده» چک کن |
| حدس از حافظه چت Session قبل | Single Source of Truth = فایل‌های ریپو |

**تنها استثنا برای درخواست متن از کاربر:**  
- کاربر **فقط ID** داد و fetch ممکن نیست  
- یا کاربر **صریحاً** گفت «برای این پروژه پیشنهاد بده» و متن/اسکرین فرستاد  
- یا **همه** کاندیدهای مناسب رد/Skip/انتخاب‌شده بودند → یک خط بگو «کاندید باز نماند» + خلاصه Skip

## ترتیب اجرا (Decision Tree)

```
کاربر: «پونیشا» یا «بعدی»
    │
    ▼
[1] Startup Check → config/session-startup-check.md
    │   Load: AGENTS.md, MEMORY.md, این فایل, bids-log, project-status
    │   اولین پاسخ: «قوانین پروژه پونیشا بررسی شد. نسخه فعلی Workflow فعال است.»
    ▼
[2] bids-log.md → Skip + رد شده + IDهای قبلی → تکرار ممنوع
    ▼
[3] project-status.md → صف اسکن Outcome تمام شده؟
    │   ├─ اگر کاربر برای اسکن Submitted آمده → یک پروژه، نه لیست
    │   └─ اگر صف خالی → پیشنهاد جدید (مسیر [4])
    ▼
[4] جستجوی پروژه باز در ponisha.ir
    │   مهارت‌ها: config/profile.md
    │   Fit + Freshness: config/feasibility-check.md
    │   چند کاندید؛ نه اولین hit
    ▼
[5] Gate سخت — HTML هر کاندید
    │   رد فوری اگر دیدی:
    │   • «کارفرما این پیشنهاد را انتخاب کرده است»
    │   • «انتخاب کرده» (روی bid دیگر)
    │   • «پایان فرصت ارسال پیشنهاد» (برای bid جدید)
    │   • ID در bids-log / Skip / رد شده
    ▼
[6] مرحله ۰ — ارزیابی (فقط برای کاربر)
    │   قالب: config/feasibility-check.md
    │   اگر ریسک بالا / غیرممکن → توقف؛ پیشنهاد ننویس
    ▼
[7] مرحله ۱ — متن پیشنهاد + فرم پونیشا
        Copy-Friendly: config/output-format.md
        بدون عدد زمان/قیمت در متن پیشنهاد
```

---

## جستجوی پروژه (بدون درخواست از کاربر)

1. **مهارت‌ها** را از `config/profile.md` بخوان (WordPress، PHP، Python، …).
2. در `ponisha.ir` پروژه‌های **باز** جستجو کن — ترجیحاً تازه، کم‌پیشنهاد، هم‌خوان با پروفایل.
3. برای هر کاندید: `https://ponisha.ir/project/{ID}` را fetch کن.
4. از HTML بخوان: عنوان، توضیح، **بازه بودجه**, مهلت bid, تعداد پیشنهادها.
5. **JSON/API تنها کافی نیست** — همیشه HTML را برای «انتخاب کرده» grep کن (درس #751187).

## خروجی مورد انتظار

### مرحله ۰ — خروجی (اجباری)

**همیشه** در چت کاربر — قبل از بلوک ۱ و ۲:

```
### مرحله ۰ — ارزیابی (#{ID})

**{عنوان}**

لینک: https://ponisha.ir/project/{ID}
```

همین لینک در `config/last-proposal.md` ثبت شود.

**ممنوع:** پیشنهاد بدون لینک در مرحله ۰ — حتی اگر متن و فرم عالی باشند.

### مرحله ۱ (اگر OK)
- **بلوک ۱:** متن پیشنهاد (Copy-Friendly)
- **بلوک ۲:** فرم پونیشا — زمان، مبلغ، ۳ مرحله (`config/output-format.md`)

## بعد از «پیشنهاد دادم»

کاربر گفت **«پیشنهاد دادم»** → ردیف جدید در `config/bids-log.md`.

## تریگرهای دیگر

| کاربر گفت | عمل |
|-----------|-----|
| **بعدی** | همان «پونیشا» — کاندید بعدی (یا بعد از Skip/Lost) |
| **پیشنهاد دادم** | ثبت bids-log |
| **Lost** / اسکرین انتخاب دیگر | ثبت Lost در bids-log + project-status |
| لینک/ID مشخص + «پیشنهاد بده» | Gate [5] → مرحله ۰/۱ — **بدون** درخواست متن اضافه اگر fetch شد |
| متن/اسکرین فرستاد | همان پروژه — Gate [5] → مرحله ۰/۱ |

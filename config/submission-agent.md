# Ponisha Submission Agent — Design Document

**وضعیت:** Design Only — **پیاده‌سازی نشده**  
**تاریخ:** ۱۴۰۵/۰۵/۱۹  
**محدوده:** سند طراحی — **بدون** تغییر Proposal Engine، Negotiation Engine، یا معماری فعلی.

---

## هدف

اتوماسیون **مرحله ارسال** پیشنهاد در پونیشا — **بعد از** تأیید Human Review — با **Human-in-the-loop** قبل از Submit نهایی.

| Submission Agent **می‌کند** | Submission Agent **نمی‌کند** |
|-----------------------------|------------------------------|
| خواندن `last-proposal` (Ready) | تولید یا بازنویسی متن Proposal |
| پر کردن فرم پونیشا (پیش‌نمایش) | Human Review |
| paste متن بلوک ۱ (پس از تأیید) | Risk / Insight / Client Simulation |
| ثبت `bids-log` پس از ارسال موفق | حدس زدن «ارسال شد» بدون شواهد |

---

## جایگاه در Pipeline (آینده)

```
Proposal Engine
  → Risk / Insight / Client Simulation
  → بلوک ۱ + بلوک ۲ (پیش‌نویس)
  → Human Review Loop          ← گیت ۱ (موجود)
  → last-proposal = Ready      ← ورودی Submission Agent
  → Submission Agent           ← این سند
  → تأیید کاربر قبل Submit   ← گیت ۲ (اجباری)
  → Submit در پونیشا
  → bids-log + learning        ← خروجی
```

**قانون:** Submission Agent **فقط** بعد از Human Review فعال می‌شود — نه بعد از پیش‌نویس اول.

## ۱. فعال‌سازی بعد از Human Review

### پیش‌شرط‌ها (همه باید برقرار باشد)

| # | شرط |
|---|-----|
| ۱ | Human Review Loop تکمیل شده (`human-review-loop.md`) |
| ۲ | کاربر صریحاً تأیید کرده: «خوبه» / «ارسال کن» / «نهایی شد» — **بدون** ایراد بازنویسی |
| ۳ | `last-proposal.md` → وضعیت **Ready** |
| ۴ | ID پروژه در `bids-log` **نیست** (هنوز Submitted نشده) |
| ۵ | ID در بخش **رد شده / Skip** `bids-log` **نیست** |

### تریگرهای فعال‌سازی (آینده)

| عبارت / رویداد | عمل |
|----------------|-----|
| Human Review → تأیید بدون اصلاح | agent پیشنهاد دهد: «Submission Agent را اجرا کنم؟» |
| **«ارسال کن»** / **«submit»** | شروع Submission Agent |
| **«پیشنهاد دادم»** (دستی) | **بدون** Submission Agent — همان workflow فعلی `pending-bid-check.md` |

### اگر Human Review → بازنویسی

→ Submission Agent **اجرا نشود**  
→ `last-proposal` → Draft یا Ready (نسخه جدید)  
→ دوباره Human Review لازم است

## ۲. ورودی از `last-proposal.md`

### فیلدهای اجباری

| فیلد | کاربرد در Submission |
|------|----------------------|
| `ID پروژه` | URL پروژه، اعتبارسنجی، ثبت bids-log |
| `عنوان` | نمایش در پیش‌نمایش + bids-log |
| `مبلغ` | فیلد «مبلغ کل» فرم |
| `زمان تحویل` | فیلد «زمان تحویل» (فقط عدد روز) |
| `متن Proposal (بلوک ۱)` | paste در چت پیشنهاد پونیشا |
| `لینک پروژه` | ناوبری مرورگر / MCP |
| `وضعیت` | باید **Ready** باشد |

### فیلدهای اختیاری (در صورت وجود در last-proposal)

| فیلد | کاربرد |
|------|--------|
| مراحل ۱–۳ (عنوان + مبلغ) | فیلدهای پرداخت امن |
| `Human Review` یادداشت | لاگ داخلی — نه ارسال به پونیشا |
| تاریخ تولید | bids-log |

### فیلدهای **خارج** از last-proposal (منبع دیگر)

| داده | منبع |
|------|------|
| ساختار مراحل (اگر در last-proposal نبود) | بلوک ۲ آخرین خروجی Proposal / `milestones-guide.md` |
| اعتبار بودجه | `pricing-guide.md` — مبلغ داخل بازه پروژه |
| رد خودکار | `bids-log` → رد شده / Skip |

### اعتبارسنجی قبل از ادامه

```
IF وضعیت ≠ Ready          → STOP — «Human Review / Ready لازم است»
IF ID در bids-log           → STOP — «قبلاً ثبت شده»
IF ID در رد شده/Skip        → STOP — «پروژه رد شده»
IF متن بلوک ۱ خالی         → STOP
IF مبلغ یا زمان خالی       → STOP
IF مبلغ خارج از بازه brief → STOP — «بودجه نامعتبر»
```

## ۳. پر کردن فرم پونیشا

### ترتیب فیلدها (طبق `output-format.md`)

| # | فیلد پونیشا | مقدار از |
|---|-------------|----------|
| ۱ | **متن چت پیشنهاد** | `last-proposal` → بلوک ۱ (code block) |
| ۲ | زمان تحویل | عدد روز — بدون «روز» |
| ۳ | مبلغ کل | عدد با جداکننده هزارگان — بدون «تومان» |
| ۴–۹ | مرحله ۱ + مبلغ ۱ + مرحله ۲ + … | last-proposal یا milestones |

### قواعد paste

- **بلوک ۱:** فقط متن چت — بدون عنوان «متن پیشنهاد:»
- **فرم:** هر فیلد جدا — مطابق code blockهای کپی‌پذیر `output-format.md`
- **ممنوع:** قیمت/زمان داخل متن چت (اگر بود → STOP و گزارش خطا)

### روش اجرا (آینده — یکی از این‌ها)

| روش | توضیح |
|-----|--------|
| **A — مرورگر (Computer Use / MCP)** | باز کردن `لینک پروژه` → کلیک «ارسال پیشنهاد» → paste فیلدها |
| **B — نیمه‌دستی** | agent فیلدها را در چت نمایش دهد؛ کاربر copy-paste کند |
| **C — API پونیشا** | فقط اگر API رسمی/پایدار موجود شد — فعلاً در design فرض **نشده** |

**پیشنهاد design:** شروع با **B** (کم‌ریسک) → بعد **A** با گیت تأیید.

## ۴. گیت تأیید کاربر — قبل از Submit نهایی

### اصل: **هرگز Submit خودکار بدون تأیید**

Submission Agent **باید** در این نقطه **متوقف** شود:

```
┌─────────────────────────────────────────┐
│  پیش‌نمایش ارسال — #ID — [عنوان]       │
├─────────────────────────────────────────┤
│  □ متن چت (بلوک ۱)                      │
│  □ زمان: X روز                          │
│  □ مبلغ: X                              │
│  □ مراحل ۱–۳                            │
│  □ لینک پروژه                           │
└─────────────────────────────────────────┘

آیا در پونیشا Submit نهایی کنم؟

  • «بله، ارسال کن»     → Submit
  • «صبر کن»            → Ready بماند، بدون تغییر
  • «اصلاح کن»          → برگشت به Human Review / ویرایش last-proposal
  • «لغو»               → Ready بماند یا Skip (با تأیید)
```

### چک‌های نمایشی در پیش‌نمایش

- ID پروژه با URL یکی باشد
- جمع مراحل = مبلغ کل
- متن بلوک ۱ بدون عدد قیمت/زمان
- مبلغ داخل بازه بودجه (اگر brief در دسترس است)

### بعد از «بله، ارسال کن»

1. اجرای Submit (روش A یا B)
2. **منتظر شاهد موفقیت** — نه حدس
3. پس از موفقیت → بخش ۵

## ۵. آپدیت `bids-log` بعد از ارسال موفق

### شواهد موفقیت (حداقل یکی)

| شواهد | کافی؟ |
|--------|--------|
| اسکرین «پیشنهادی که شما ارسال کرده‌اید» | **بله** |
| پیام تأیید پونیشا در UI | **بله** |
| کاربر گفت «پیشنهاد دادم» + ID مطابق | **بله** |
| Submit کلیک شد ولی شاهد نیست | **خیر** — bids-log آپدیت **نشود** |

### عملیات ثبت (طبق `pending-bid-check.md`)

**۱. `bids-log.md` — جدول اصلی**

| تاریخ | ID | عنوان | مبلغ | زمان | وضعیت |
|-------|-----|--------|------|------|--------|
| امروز (شمسی) | … | … | … | … | **Submitted** |

**۲. `bids-log.md` — جزئیات Proposal** (در صورت وجود بخش)

- متن ارسال‌شده (بلوک ۱)
- منبع ثبت: `Submission Agent` + نوع شواهد

**۳. `last-proposal.md`**

- وضعیت → **Submitted**
- `در bids-log` → **بله**
- `تاریخ ثبت bids-log` → تاریخ
- یادداشت: `Submitted via Submission Agent — [شواهد]`

**۴. `proposal-learning.md`** (در صورت وجود)

- ردیف اولیه «پیشنهاد دادم» — **بدون** Lesson جدید

**۵. commit**

```
bids-log: #ID Submitted (submission-agent)
```

## ۶. مدیریت خطا

### دسته‌بندی خطاها

| کد | خطا | واکنش |
|----|-----|--------|
| **E01** | `last-proposal` نیست / Ready نیست | STOP — Human Review لازم |
| **E02** | ID قبلاً در bids-log | STOP — تکراری |
| **E03** | ID در رد شده / Skip | STOP |
| **E04** | مبلغ خارج از بازه بودجه | STOP — اصلاح فرم |
| **E05** | متن بلوک ۱ شامل قیمت/زمان | STOP — اصلاح متن |
| **E06** | جمع مراحل ≠ مبلغ کل | STOP — اصلاح milestones |
| **E07** | پروژه بسته / کارفرما فریلنسر انتخاب کرده | ثبت Skip یا Lost — **بدون** Submit |
| **E08** | خطای login پونیشا / session منقضی | گزارش به کاربر — ارسال دستی |
| **E09** | timeout / UI پونیشا تغییر کرده | fallback به روش B (copy-paste دستی) |
| **E10** | Submit زده شد — شاهد موفقیت نیست | **Ready بماند** — bids-log **آپدیت نشود** |
| **E11** | کاربر «لغو» / «صبر کن» | بدون تغییر — Ready |
| **E12** | شبکه / MCP / مرورگر در دسترس نیست | پیشنهاد ارسال دستی + checklist |

### قواعد کلی خطا

1. **هرگز حدس نزن** — مخصوصاً E10 (هم‌راستا با `pending-bid-check.md`)
2. **Ready ≠ Submitted** تا شواهد نباشد
3. خطا → وضعیت را **گم نکن** — last-proposal باید قابل retry باشد
4. خطای E07 → `bids-log` رد شده یا Lost — نه Submitted
5. **Lesson از خطا ساخته نشود** — فقط لاگ در یادداشت agent

### Retry

| خطا | Retry مجاز؟ |
|-----|-------------|
| E08, E09, E12 | **بله** — بعد از رفع توسط کاربر |
| E04, E05, E06 | **بله** — بعد از اصلاح last-proposal + Human Review |
| E02, E03, E07 | **خیر** |

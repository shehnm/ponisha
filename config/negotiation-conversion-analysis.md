# Negotiation Conversion Analysis — تحلیل تبدیل مذاکره به قرارداد

**هدف:** بعد از هر پاسخ کارفرما و هر مذاکره، **فقط کیفیت پاسخ** را بررسی نکن — بررسی کن **چرا گفتگو به قرارداد تبدیل شد یا نشد**.

**محدوده:** فقط **Learning و Analysis** — **جایگزین Proposal Engine یا Negotiation Engine نیست.**

| موتور | وظیفه | این فایل |
|--------|--------|----------|
| **Proposal Engine** | اولین پاسخ کارفرما | ❌ تغییر نمی‌کند |
| **Negotiation Engine** | Pipeline پاسخ مذاکره (#21) | ❌ تغییر نمی‌کند |
| **Negotiation Conversion Analysis** | یادگیری از funnel و مانع تبدیل | ✅ فقط تحلیل و ثبت |

**ارتباط:**
- `proposal-learning.md` — Lessons، Human Review، اسکیما کلی
- `project-status.md` — وضعیت Negotiation / Won / Lost
- `bids-log.md` — ثبت سریع per پروژه
- `proposal-generation-logic-analysis.md` — تحلیل منطق Proposal اولیه (مکمل)
- `project-selection-decision-analysis.md` — آیا از اول پروژه درست انتخاب شده بود؟ (Lost attribution)
- `emotional-trust-layer-analysis.md` — آیا Proposal اعتماد انسانی ساخت؟ (مانع «اعتماد کم»)
- `proposal-intent-control.md` — Stage ۱/۲/۳؛ نگاشت Funnel ↔ Intent

## چه زمانی اجرا شود

| تریگر | عمل |
|--------|-----|
| «پاسخ داد» / «کارفرما جواب داد» | Funnel + تحلیل پیام کارفرما + **پیشنهاد هدف پاسخ بعدی** |
| بعد از **هر پاسخ مذاکره** (قبل/بعد Human Review) | آیا پاسخ ما مرحله بعد را جلو برد؟ مانع؟ |
| «بردیم» | ثبت Won + **عوامل مؤثر** در تبدیل |
| «باختیم» / Lost | ثبت Lost + **عوامل مانع** — بدون Lesson جدید در Engine |
| بررسی دوره‌ای Negotiation | پروژه‌های Submitted با گفتگو باز — اسکن funnel |

**شرط ورود به تحلیل:** حداقل یکی از این‌ها رخ داده باشد:
- کارفرما پاسخ داده
- سؤال پرسیده
- نمونه خواسته
- قیمت/Scope را بررسی کرده

## Funnel — مراحل تبدیل

برای هر پروژه، **مرحله فعلی** را مشخص کن (یک مرحله اصلی + یادداشت جزئی):

| مرحله | معنی | سیگنال معمول |
|--------|------|----------------|
| **Proposal دیده شد** | bid ارسال شده؛ کارفرما هنوز تعامل نکرده | Submitted، بدون پیام |
| **پاسخ کارفرما** | اولین پیام کارفرما (هر نوع) | سؤال، سلام، درخواست جزئیات |
| **مذاکره** | گفتگوی چندمرحله‌ای scope/روش/زمان | چند رفت‌وبرگشت |
| **درخواست نمونه** | نمونه‌کار، لینک، دمو، رفرنس | «نمونه بفرست»، «کار قبلی» |
| **بررسی قیمت** | بحث مبلغ، بودجه، تخفیف، مقایسه | «قیمت»، «گران»، «بودجه» |
| **انتخاب** | Won — کارفرما shehneh را انتخاب کرد | «انتخاب کرده» روی bid ما |
| **Lost** | کارفرما فرد دیگر را انتخاب کرد یا گفتگو مرد | Lost در bids-log |

**قانون:** مرحله را **بر اساس آخرین تعامل واقعی** به‌روز کن — نه بر اساس امید.

## تحلیل اجباری (هر رویداد مذاکره)

### ۱. مرحله Funnel فعلی

```markdown
| فیلد | مقدار |
|------|--------|
| ID | |
| لینک | https://ponisha.ir/project/{ID} |
| مرحله Funnel | Proposal دیده شد / پاسخ کارفرما / … |
| تاریخ آخرین تعامل | |
| تعداد پیام کارفرما | |
| تعداد پاسخ ما | |
```

### ۲. آیا پاسخ ما باعث حرکت به مرحله بعد شد؟

| پاسخ | معنی |
|------|------|
| **بله — جلو رفت** | کارفرما scope/قیمت/نمونه/قدم بعدی را مطرح کرد |
| **بله — حفظ شد** | گفتگو ادامه یافت بدون عقب‌رفت |
| **خیر — سکوت** | بعد از پاسخ ما پیام جدید نیامد (هنوز زود است اگر <۴۸h) |
| **خیر — عقب‌رفت** | کارفرما سرد شد، «فعلاً نه»، یا موضوع عوض شد |
| **نامشخص** | زمان کافی نگذشته |

**یادداشت کوتاه:** کدام جمله/بخش پاسخ احتمالاً جلو یا عقب برد؟

### ۳. آیا مانع انتخاب وجود دارد؟

اگر **بله** → دسته‌بندی مانع (یک یا چند مورد):

| دسته مانع | تعریف | سیگنال |
|-----------|--------|---------|
| **اعتماد کم** | شک به توانایی، تجربه، یا جدیت | «مطمئن نیستم»، «اولین بار» |
| **نمونه‌کار کم** | پورتfolio/رفرنس کافی نیست | «نمونه بفرست»، «کار مشابه» |
| **قیمت** | مبلغ بالا/پایین/نامشخص | «گران»، «بودجه کمتر»، مقایسه |
| **پاسخ طولانی** | پاسخ ما خوانده نشده یا overwhelm | سکوت بعد از پاسخ بلند |
| **جواب ندادن به دغدغه اصلی** | سؤال مهم بی‌پاسخ یا کناری | تکرار سؤال، نارضایتی |
| **رقیب قوی‌تر** | فریلنسر دیگر جلوتر یا ارزان‌تر | اشاره به پیشنهاد دیگر |
| **Scope نامشخص** | ابهام محدوده — تصمیم نمی‌گیرد | «دقیقاً شامل چیست» |
| **نیاز کارفرما تغییر کرده** | brief عوض شد | اطلاعات جدید متناقض |

**اولویت مانع:** کدام **یکی** الان بیشترین اثر را دارد؟

### ۴. قبل از پاسخ بعدی — هدف پیشنهادی

**قبل از نوشتن پاسخ بعدی** (مکمل Pipeline Negotiation Engine #21):

| هدف پیام | وقتی اولویت دارد |
|----------|------------------|
| **فقط جواب سؤال** | سؤال مشخص و ساده — risk over-selling |
| **اعتمادسازی** | مانع = اعتماد کم / نمونه‌کار |
| **بستن قرارداد** | scope و قیمت توافق شده — فقط قدم عملی |
| **گرفتن اطلاعات لازم** | بدون داده نمی‌توان قیمت/زمان/scope نهایی کرد |
| **پیشنهاد قدم بعدی** | گفتگو گیر کرده — یک قدم کوچک عملی (#20) |

**خروجی agent (خلاصه برای کاربر):**

```markdown
**هدف پیشنهادی پاسخ بعدی:** [یکی از موارد بالا]
**دلیل:** [یک جمله — بر اساس مانع/funnel]
**نباید:** [مثلاً تعهد جدید / پاسخ بلند / فنی غیرضروری]
```

> **تفکیک:** Negotiation Engine **می‌نویسد**؛ این بخش **تحلیل می‌کند** چرا و به کدام سمت باید برود.

### ۵. بعد از نتیجه واقعی — برد/باخت

وقتی Won یا Lost ثبت شد:

| فیلد | Won | Lost |
|------|-----|------|
| مرحله نهایی Funnel | انتخاب | Lost |
| عامل مؤثر #1 | … | … |
| عامل مؤثر #2 | (اختیاری) | … |
| آخرین پاسخ مذاکره مؤثر؟ | بله/خیر/نامشخص | … |
| قیمت نسبت به رقبا | … | … |
| زمان پاسخ‌گویی ما | … | … |

**عامل مؤثر:** از همان دسته‌های مانع + «پاسخ خوب»، «سؤال پایانی Proposal»، «قدم بعدی (#20)».

**قانون Lost:** Lesson جدید در Engine **نساز** — فقط اینجا و `proposal-learning` تحلیل نهایی.

## مقایسه و الگو (دوره‌ای)

هر **۵** رویداد مذاکره یا **ماهانه** (هرکدام زودتر):

1. کدام **مانع** بیشتر تکرار شد؟
2. کدام **هدف پاسخ** با Won هم‌راستا بود؟
3. آیا «پاسخ طولانی» یا «جواب ندادن به دغدغه» در Lostها تکرار شد؟
4. Funnel کجا **بیشترین ریزش** را دارد؟ (پاسخ اول → مذاکره → انتخاب)

**خروجی:** جدول خلاصه در پایین لاگ — **نه** تغییر Engine مگر کاربر + Freeze تأیید کند.

## ترتیب اجرا (با Negotiation Engine)

```
پیام جدید کارفرما
  → Negotiation Engine Pipeline (#21) — تولید پاسخ
  → Human Review
  → **Negotiation Conversion Analysis** (این فایل) — funnel + مانع + هدف بعدی
  → در صورت Won/Lost → تحلیل عوامل (#5) + proposal-generation-logic-analysis
```

**هرگز:** قوانین Pipeline مذاکره را در این فایل بازنویسی نکن — فقط **ارجاع** بده.

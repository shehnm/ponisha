# Emotional Trust Layer — Proposal Psychology Analysis

**هدف:** در کنار تحلیل **فنی** Proposal، بررسی شود آیا متن باعث **اعتماد انسانی** و احساس «این فرد پروژه من را **فهمیده**» می‌شود یا نه.

**محدوده:** فقط **تحلیل و معیار کیفیت** — **Proposal Engine اصلی تغییر نمی‌کند.**

| لایه | وظیفه | این فایل |
|------|--------|----------|
| **Proposal Engine** | Risk + Insight + Simulation | ❌ تغییر نمی‌کند |
| **Emotional Trust Layer** | روان‌شناسی اعتماد + **Client Perspective Simulation** | ✅ معیار کیفیت قبل از Human Review |

**اصل:**

کارفرما معمولاً فقط دنبال **ارزان‌ترین** یا **فنی‌ترین** فرد نیست. در میان Proposalهای زیاد، به پیشنهادی توجه می‌کند که نشان دهد:

- مشکل **واقعی** او فهمیده شده
- **نگرانی‌های پنهان** دیده شده
- مسیر همکاری **امن و قابل پیش‌بینی** است

**ارتباط:**
- `proposal-engine.md` — Client Simulation (فنی) — **مکمل**، نه جایگزین
- `human-review-loop.md` — **ارتباط انسانی** + **دید کارفرما** ⭐ ۱–۵
- `proposal-generation-logic-analysis.md` — ساختار و منطق Proposal
- `negotiation-conversion-analysis.md` — مانع «اعتماد کم»
- `personal-voice.md` — ممنوعیت لحن فروشنده و کلیشه
- `proposal-learning.md` — ثبت Human Review + Lessons

## ۱. نگرانی انسانی کارفرما

**قبل از نوشتن یا بازنویسی بلوک ۱** — از brief و دسته پروژه، **حداقل یک** نگرانی انسانی را شناسایی کن (نه فقط فنی):

| نگرانی رایج | سیگنال در brief |
|-------------|------------------|
| **ترس از خراب شدن سایت/سیستم فعلی** | «سایت فعال است»، migration، redesign |
| **ترس از هزینه‌های پنهان** | بودجه محدود، «شفاف»، scope مبهم |
| **ترس از انتخاب فرد اشتباه** | پروژه حساس، اولین بار فریلنسر |
| **ترس از تأخیر** | deadline، رویداد، فصل فروش |
| **ترس از تنها ماندن بعد از تحویل** | پشتیبانی، آموزش، handover |
| **کسی کسب‌وکار را نفهمد** | برند، B2B تخصصی، صنعت خاص |

```markdown
| فیلد | مقدار |
|------|--------|
| ID | |
| **نگرانی انسانی #1** | |
| **نگرانی انسانی #2** (اختیاری) | |
| **منبع (brief)** | نقل‌قول یا اشاره مستقیم |
```

**قانون:** اگر نگرانی را از brief نمی‌توانی استنتاج منطقی کنی → **حدس نزن** — فقط نگرانی‌های قابل اتکا.

---

## ۲. نقطه اتصال انسانی

Proposal باید **یک نقطه اتصال انسانی** داشته باشد — نه تعریف مصنوعی؛ **یک جمله** که نشان دهد پروژه **فهمیده شده**.

| ❌ ضعیف | ✅ بهتر |
|---------|---------|
| «من متخصص حرفه‌ای و با تجربه هستم.» | «با توجه به اینکه سایت فعلی شما فعال است، مهم‌ترین نکته این است که بازطراحی باعث از دست رفتن ساختار سئو و رتبه‌های فعلی نشود.» |
| «با افتخار در خدمت شما هستم.» | «اگر محصولات زیاد باشند، از همان اول ساختار ورود اطلاعات مشخص شود تا وسط کار دوباره‌کاری نشود.» |
| «تضمین کیفیت می‌دهم.» | «قبل از انتقال کامل، چند محصول نمونه منتقل می‌کنم تا ساختار دسته‌بندی را با هم تأیید کنیم.» |

**چک agent (قبل از Human Review):**

```markdown
- [ ] حداقل **یک جمله** نگرانی انسانی کارفرما را منعکس می‌کند؟
- [ ] آن جمله **مخصوص این پروژه** است (نه قالب عمومی)؟
- [ ] بدون کلیشه اعتمادسازی (`personal-voice.md`)؟
```

---

## ۳. احساس آشنایی — بدون داستان‌سازی

کارفرما باید حس کند: **«این فرد قبل از شروع کار، به مسئله من فکر کرده.»**

| مجاز | ممنوع |
|------|--------|
| اشاره به **جزئیات brief** | ادعای تجربه **غیرواقعی** (`profile.md` فقط) |
| پیامد **منطقی** مشکل برای کسب‌وکار | **داستان‌سازی** و سناریوی ساختگی (#9) |
| روش کار **شفاف** و قابل پیش‌بینی | جملات **فروشنده‌محور** |
| Risk + راه‌حل **مشخص** | «در خدمت شما»، «با احترام»، «خوشحال می‌شوم» |

**تفاوت با «اعتمادسازی» در Human Review:**

| اعتمادسازی (فنی/روش) | ارتباط انسانی (روانی) |
|----------------------|------------------------|
| Risk Discovery، شفافیت scope | «فهمیده شده‌ام»، «امن است همکاری» |
| تجربه **واقعی** از profile | **نگرانی پنهان** دیده شده |
| سؤال تخصصی | مسیر همکاری **قابل پیش‌بینی** |

## Client Perspective Simulation — شبیه‌سازی دید کارفرما

**هدف:** قبل از تولید Proposal، از **دید کارفرما** بررسی کن: چرا او باید بین **۲۰–۳۰ پیشنهاد**، **این** پیشنهاد را انتخاب کند؟

**زمان اجرا:** بعد از پیش‌نویس بلوک ۱، **قبل** Human Review — **داخلی** (agent).

> **تفاوت با Client Simulation (`proposal-engine`):** Engine = «آیا حداقل یک پیام می‌فرستاد؟» — این بخش = «آیا **می‌ایستد و ادامه می‌خواند** و **اعتماد** می‌کند؟»

---

### CPS-۱. وضعیت ذهنی کارفرما

از brief و دسته پروژه جواب بده:

```markdown
| سؤال | پاسخ |
|------|------|
| **الان از چه چیزی می‌ترسد؟** | (ترس اصلی — یک جمله) |
| **چه چیزی باعث شده پروژه را ثبت کند؟** | (محرک — درد/فرصت) |
| **چه ریسکی برایش مهم‌تر است؟** | فنی / مالی / زمانی / reputational |
| **چه چیزی باعث می‌شود به یک فرد غریبه اعتماد کند؟** | شفافیت / نمونه / روش / … |
```

**منبع:** فقط brief + استنتاج منطقی — **حدس خارج از brief ممنوع** (#9).

---

### CPS-۲. حس «این فرد پروژه من را فهمیده»

Proposal **نباید فقط** توانایی فریلنسر را معرفی کند. **حداقل یک نشانه** از هر سه:

| نشانه | ✓ | مثال در متن |
|--------|---|-------------|
| **مشکل واقعی** کارفرما فهمیده شده | | |
| **یک ریسک احتمالی** دیده شده | | |
| **مسیر اجرا** مشخص است | | |

**چک agent:**

```markdown
- [ ] هر سه نشانه پوشش داده شده یا حداقل **۲ از ۳** قوی؟
- [ ] هیچ جمله‌ای فقط «من توانم / من متخصص» است بدون اتصال به brief؟
```

*(مرتبط با بخش ۲ — نقطه اتصال انسانی)*

---

### CPS-۳. تست تفاوت (Differentiation Test)

**قبل از Human Review** — با تعداد Proposal فعلی پروژه (از مرحله ۰):

```markdown
| فیلد | مقدار |
|------|--------|
| تعداد Proposal رقیب (تقریبی) | ~… |
| **اگر این Proposal بین ۳۰ پیشنهاد مشابه باشد، چه چیز باعث مکث و ادامه خواندن می‌شود؟** | یک جمله — **مخصوص این پروژه** |
| آیا این تفاوت **فنی صرف** است یا **فهم مسئله**؟ | فهم / فنی / ترکیب |
| آیا تفاوت **کپی‌پذیر** است (هر کسی می‌تواند بنویسد)؟ | بله → ضعیف / خیر → قوی |
```

**آستانه:** اگر «مکث» = نامشخص یا تفاوت کپی‌پذیر → **بازنویسی** قبل از Human Review.

---

### CPS-۴. جلوگیری از اعتماد مصنوعی

**ممنوع:**

| ❌ | مثال |
|----|------|
| تعریف از خود | «بهترین انتخاب»، «متخصص حرفه‌ای» |
| تجربه ثبت‌نشده | خارج از `profile.md` |
| جملات احساسی کلیشه‌ای | «با افتخار»، «در خدمت شما» |
| «سال‌ها تجربه» بدون ارتباط پروژه | عمومی و بی‌ربط |

**اعتماد فقط از:**

| ✅ | منبع |
|----|------|
| **فهم مسئله** | جزئیات brief |
| **کاهش ریسک** | Risk Discovery |
| **روش اجرای روشن** | مراحل / قدم بعدی (#20) |
| **نمونه واقعی** | `profile.md` — بدون اختراع |
| **قدم بعدی مشخص** | سؤال پایانی / اقدام اول |

---

### CPS-۵. Psychology Simulation (خلاصه)

**بعد از CPS-۱ تا CPS-۴** — تأیید نهایی:

| سؤال | پاسخ |
|------|------|
| کارفرما **فقط دنبال پروژه** است؟ | بله → بازنویسی |
| **مسئولیت نتیجه** را درک کرده؟ | خیر → بازنویسی |
| **یک جمله** بیشترین اعتماد | … |
| **یک جمله** بیشترین فاصله (اگر هست) | … |

*(جایگزین بخش ۴ قبلی — همان منطق، داخل CPS)*

## Pattern Break Analysis — شکستن الگوی تکراری

**هدف:** بررسی اینکه Proposal در **چند ثانیه اول** چه دارد که کارفرma آن را **مثل پیشنهادهای تکراری رد نکند**.

**زمان اجرا:** بعد از CPS، **قبل** Human Review — **داخلی** (agent).

> **تفاوت با CPS-۳:** CPS-۳ = تفاوت کل متن در میان ۳۰ bid — Pattern Break = **۲ جمله اول** و **حذف کلیشه** قبل از اسکن کامل.

---

### PBA-۱. First Impression Test

**فقط ۲ جمله اول** بلوک ۱ را جدا کن و بپرس:

```markdown
| سؤال | پاسخ |
|------|------|
| جمله ۱ + ۲ (نقل) | «…» |
| **فقط معرفی توانایی** است؟ | بله / خیر |
| **نشانه فهم پروژه** دارد؟ | بله / خیر |
| کارفرما در ۵ ثانیه **ادامه می‌دهد** یا رد می‌کند؟ | ادامه / رد / نامشخص |
```

**آستانه:**

| نتیجه | اقدام |
|--------|--------|
| معرفی توانایی = **بله** و فهم پروژه = **خیر** | **بازنویسی شروع** — قبل از Human Review |
| هر دو **خیر/بله** نامشخص | بازبینی — شروع را به brief وصل کن |

---

### PBA-۲. حذف جملات تکراری

**کلمات/جملات عمومی** که همه می‌نویسند — در متن **شناسایی** و **حذف/جایگزین**:

| ❌ بدون ارزش تصمیم‌گیری | جایگزین |
|-------------------------|---------|
| «متخصص حرفه‌ای هستم» | جزئیات brief یا Risk |
| «سال‌ها تجربه دارم» | تجربه **مرتبط** از `profile.md` — یک جمله |
| «با کیفیت انجام می‌دهم» | روش یا قدم عملی |
| «آماده همکاری هستم» | سؤال پایانی یا قدم بعدی |
| «سلام، وقت بخیر» طولانی + معرفی خود | «سلام وقت بخیر» → **مستقیم دغدغه** ([Human][Keep]) |

**چک agent:**

```markdown
- [ ] هیچ **یکی** از جملات بالا به‌تنهایی در ۲ جمله اول نیست؟
- [ ] اگر «تجربه» آمد → **مربوط به همین پروژه** است؟
```

*(مکمل `personal-voice.md` و CPS-۴)*

---

### PBA-۳. ایجاد نقطه مکث

Proposal باید **حداقل یک** از این‌ها را در **شروع یا میانه کوتاه** داشته باشد:

| نوع نقطه مکث | ✓ | محل در متن |
|--------------|---|------------|
| **نکته مخصوص همان پروژه** | | |
| **ریسک** که کارفرما شاید ندیده باشد | | |
| **پیشنهاد کوچک برای شروع** | | |
| **سؤال هوشمندانه** | | |

**قانون:** اگر **هیچ** ✓ → بازنویسی قبل از Human Review.

*(مرتبط با CPS-۳ — «مکث»؛ PBA روی **محل و نوع** در چند ثانیه اول تمرکز دارد)*

---

### PBA-۴. Human Review — معیار «شکست الگو»

**در `human-review-loop.md`** — **هشتمین** معیار:

| بخش | سؤال راهنما |
|-----|-------------|
| **شکست الگو (Pattern Break)** | «آیا این Proposal در بین **۳۰ پیشنهاد مشابه**، دلیل کافی برای **خواندن ادامه متن** ایجاد می‌کند؟» |

---

## ۵. Human Review — معیارهای روان‌شناسی

**در `human-review-loop.md`** — سه معیار روان‌شناسی (+ پنج معیار کلاسیک):

| بخش | سؤال راهنما |
|-----|-------------|
| **ارتباط انسانی** | «اگر من کارفرما بودم، آیا حس می‌کردم این فرد **قبل از گرفتن پروژه** به مشکل من **فکر کرده** است؟» |
| **دید کارفرما** | «آیا کارفرma **فقط دنبال گرفتن پروژه نیست**، بلکه **قبل از شروع به نتیجه فکر کرده** است؟» |
| **شکست الگو** | «آیا در بین **۳۰ پیشنهاد مشابه**، دلیل کافی برای **ادامه خواندن** هست؟» |

**ثبت در `proposal-learning.md`:**

```markdown
| Human Review | شروع / اعتماد / درک / لحن / سؤال / **ارتباط انسانی** / **دید کارفرما** / **شکست الگو** |
| Client Perspective | ترس / محرک / تفاوت (مکث) / اعتماد مصنوعی؟ |
| Pattern Break | ۲ جمله اول / کلیشه حذف شد؟ / نقطه مکث |
```

**Lesson از امتیاز پایین (≤۲):**
- `[Human]` — CPS: تفاوت ضعیف / اعتماد مصنوعی / فقط معرفی توانایی
- `[Human]` — PBA: شروع کلیشه‌ای / ۲ جمله اول بدون فهم پروژه / بدون نقطه مکث
- **نه** تغییر خودکار Engine

**`[Human][Keep]` از امتیاز بالا (≥۴):**
- جمله/زاویه «فهمیده شدن»، «تفکر به نتیجه»، یا **شروع Pattern Break** — حفظ شود

## ترتیب با Pipeline Proposal

```
Selection Analysis
  → Proposal Engine (Risk + Insight + Simulation)
  → **Emotional Trust (۱–۳) + CPS (۱–۵) + Pattern Break (PBA-۱–۳)** ← قبل از Human Review
  → Human Review (+ ارتباط انسانی + دید کارفرما + شکست الگو ⭐)
  → نسخه نهایی
```

**Negotiation:** اگر مانع = «اعتماد کم» در `negotiation-conversion-analysis` → بازبینی نقطه اتصال انسانی Proposal اولیه — **نه** بازنویسی Engine.

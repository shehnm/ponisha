# مدیریت وضعیت پروژه‌های پونیشا

**هدف:** پروژه‌های باز، Lost، Won و **Skip** را قابل پیگیری نگه دار — Win Rate و انتخاب پروژه واقع‌بینانه بماند.

**محدوده:** Project Selection + وضعیت + گزارش دوره‌ای — **نه** Proposal Engine، **نه** Lesson متن پیشنهاد.

**ارتباط:** `feasibility-check.md` — ارزیابی اولیه + سیگنال فعالیت کارفرما؛ `bids-log.md` — ثبت سریع per پروژه.

---

## گزارش دوره‌ای — پروژه‌های Skip

**هدف:** بازبینی دستی پروژه‌هایی که bid نشده‌اند.

### قالب جدول Skip (در گزارش یا `bids-log`)

| تاریخ | ID | عنوان | لینک | دلیل Skip | عدم فعالیت کارفرما |
|-------|-----|--------|------|-----------|---------------------|
| … | … | … | `https://ponisha.ir/project/{ID}` | … | بله / خیر |

**قوانین:**
- هر Skip **با دلیل** ثبت شود — نه فقط ID
- اگر دلیل اصلی **عدم فعالیت کارفرما** بود → ستون «عدم فعالیت کارفرما = **بله**» (جدا از سایر دلایل مثل mismatch پروفایل)
- **لینک مستقیم** پروژه برای بازبینی دستی **اجباری**

## وضعیت‌های استاندارد (پس از Submit)

| وضعیت | معنی |
|--------|------|
| **Submitted** | پیشنهاد ارسال شده؛ نتیجه مشخص نیست |
| **Waiting for client** | کارفرما هنوز فریلنسر انتخاب نکرده |
| **Negotiation** | گفتگو با کارفرما ادامه دارد |
| **Won** | پروژه گرفته شد |
| **Lost** | کارفرما فرد دیگری را انتخاب کرد |
| **Skip** | ارزیابی شد؛ bid نشد (دلیل در `bids-log` / جدول بالا) |

---

## تشخیص Lost

اگر در صفحه پروژه روی پیشنهاد **فریلنسر دیگر** نوشته باشد:

> **کارفرما این پیشنهاد را انتخاب کرده است**

→ **Status = Lost** — ثبت در `bids-log.md` بخش «نتایج Lost». **Lesson جدید نساز** مگر الگوی تکرارشونده.

## بررسی دوره‌ای وضعیت (Submitted / Lost)

**تریگر:** بعد از هر **۱۰** پیشنهاد ارسال‌شده **یا** **هفته‌ای یک‌بار** — از کاربر بپرس آیا پروژه‌های قبلی را برای Lost اسکن کند.

| فیلد | مقدار |
|------|--------|
| آخرین بررسی دوره‌ای | **۱۴۰۵/۰۵/۱۸** |
| تاریخ بعدی (حداکثر) | ۱۴۰۵/۰۵/۲۵ |

**عمل:** صفحه هر پروژه باز در `bids-log` — وجود انتخاب فریلنسر دیگر → Lost.

---

## Win Rate

`Won / (Won + Lost)` — فقط پروژه‌های **حل‌شده**. Skip در Win Rate حساب **نمی‌شود**.

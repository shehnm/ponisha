# Project Selection Decision Analysis — تحلیل تصمیم انتخاب پروژه

**هدف:** قبل از ساخت هر Proposal بررسی شود **چرا این پروژه انتخاب شد** و آیا انتخاب آن **منطقی** بوده است.

**محدوده:** فقط **Learning و Analysis** — **جایگزین `feasibility-check.md`، Proposal Engine یا Negotiation Engine نیست.**

| لایه | وظیفه | این فایل |
|------|--------|----------|
| **`feasibility-check.md`** | ارزیابی Go/No-Go + مرحله ۰ | ❌ تغییر نمی‌کند — **ورودی** |
| **Proposal Engine** | ساخت پیشنهاد | ❌ تغییر نمی‌کند |
| **Project Selection Decision Analysis** | ثبت **چرا** bid + یادگیری از نتیجه | ✅ فقط تحلیل |

**هدف نهایی:**

سیستم فقط یاد **نگیرد** «چگونه پیشنهاد بدهد» — یاد **بگیرد** «**برای چه پروژه‌ای** پیشنهاد بدهد».

**ارتباط:**
- `feasibility-check.md` — معیارهای انتخاب و مرحله ۰ (منبع داده اولیه)
- `project-status.md` — Skip، Fresh bids، Win Rate
- `bids-log.md` — ثبت bid / Skip
- `proposal-generation-logic-analysis.md` — منطق Proposal (بعد از Submit)
- `negotiation-conversion-analysis.md` — funnel مذاکره (بعد از پاسخ کارفرما)
- `proposal-learning.md` — Lessons کلی

---

## چه زمانی اجرا شود

| مرحله | تریگر | عمل |
|--------|--------|-----|
| **قبل از Proposal** | «پونیشا» / «بعدی» → پروژه انتخاب شد | **ثبت دلیل انتخاب + امتیاز + گزینه رد** (بخش ۱–۳) |
| **Skip** | کاربر bid نکرد | ثبت **چرا رد شد** + پروژه‌های با اولویت بالاتر |
| «پیشنهاد دادم» | Submit | تأیید ثبت انتخاب — لینک به همین ID |
| «بردیم» | Won | **بازبینی معیارهای انتخاب** — درست بود؟ (بخش ۴) |
| «باختیم» / Lost | Lost | **تفکیک خطا:** انتخاب / Proposal / مذاکره / بیرونی (بخش ۴) |

**قانون:** اگر مرحله ۰ (`feasibility-check`) انجام شد و Proposal ساخته می‌شود → **بخش ۱–۳ اجباری** قبل از بلوک ۱.

---

## ۱. دلیل انتخاب پروژه

برای هر پروژه **قبل از Proposal**، موارد زیر را علامت بزن (✓ / ✗ / جزئی) + **یک جمله توضیح**:

| معیار | ✓/✗ | یادداشت |
|--------|-----|---------|
| **تطابق با تخصص اصلی** | | stack و دسته در `profile.md` |
| **تجربه مشابه قبلی** | | Won / Negotiation / Lesson مرتبط |
| **نمونه قابل ارائه** | | پورتfolio، لینک، پروژه واقعی |
| **احتمال برد** | | Fit + رقابت + Freshness |
| **ارزش مالی** | | بودجه vs زمان |
| **امکان رابطه بلندمدت** | | تکرار، نگهداری، مشتری بالقوه |
| **تازه بودن پروژه** | | Fresh Project Priority |
| **فعالیت کارفرما** | | بالا / پایین / نامشخص |

**دلیل اصلی انتخاب (۱–۲ جمله):** چرا **این** پروژه از بین کاندیداها برنده شد؟

**منبع:** خروجی مرحله ۰ `feasibility-check.md` — این بخش **ثبت و یادگیری** است، نه تکرار ارزیابی.

---

## ۲. امتیازدهی انتخاب

هر بُعد **۱–۵** (۱ = ضعیف، ۵ = عالی). **جمع** = Selection Score (۶–۳۰).

| بُعد | ۱ | ۳ | ۵ | امتیاز |
|------|---|---|---|--------|
| **Skill Fit** — تناسب مهارت | خارج تخصص | قابل انجام | هسته تخصص | |
| **Proof Fit** — نمونه و تجربه قابل اثبات | بدون رفرنس | جزئی | Won/نمونه مشابه | |
| **Competition Risk** — ریسک رقابت *(معکوس: ۵ = رقابت کم)* | >۳۰ bid | ~۱۰–۲۰ | ۰–۵ bid + Fresh | |
| **Client Activity** — فعال بودن کارفرما | >۷ روز سکوت | متوسط | اخیراً فعال | |
| **Budget Fit** — تناسب بودجه | خارج بازه / تنگ | داخل بازه | بالای میانه / Odoo-tier | |
| **Strategic Value** — ارزش بلندمدت | یک‌بار، کم‌حاشیه | استاندارد | تکرار / ERP / نگهداری | |

**آستانه پیشنهادی (راهنما — نه قانون سخت):**

| Selection Score | توصیه |
|-----------------|--------|
| **۲۴–۳۰** | bid با اطمینان — اولویت بالا |
| **۱۸–۲۳** | bid اگر زمان داری — ثبت دلیل |
| **۱۲–۱۷** | فقط با دلیل قوی (مثلاً Strategic) — یا Skip |
| **≤۱۱** | **Skip** مگر override صریح کاربر |

> Competition Risk: امتیاز **بالا** = رقابت **کم**. اگر bid زیاد → امتیاز پایین.

## ۳. بررسی گزینه رد (قبل از Proposal)

**قبل از نوشتن بلوک ۱** دو سؤال را جواب بده:

### الف) چرا این پروژه ارزش زمان گذاشتن دارد؟

```markdown
- دلیل #1: …
- دلیل #2: (اختیاری) …
- اگر فعالیت کارفرما پایین است: چرا با وجود آن bid می‌کنیم؟ (اجباری)
```

### ب) چرا پروژه‌های دیگر اولویت پایین‌تر دارند؟

```markdown
| ID / عنوان کوتاه | چرا اولویت پایین‌تر | Skip؟ |
|-------------------|---------------------|-------|
| … | Fit پایین‌تر / رقابت زیاد / … | بله/خیر |
| … | … | … |
```

**حداقل:** ۱–۲ کاندیدای رد‌شده (از جستجوی همان session یا صف ذهنی agent).

**اگر Skip:** همین بخش در `bids-log` + `project-status` ثبت شود — **Selection Analysis برای Skip** = چرا bid **نشد**.

## ۴. بررسی بعد از نتیجه

### اگر Won

| سؤال | پاسخ |
|------|------|
| آیا **معیارهای انتخاب** درست بودند؟ | بله / جزئی / خیر |
| کدام بُعد امتیاز (بخش ۲) بیشترین هم‌راستایی با Win داشت؟ | |
| آیا پروژه‌های رد‌شده (بخش ۳-ب) واقعاً اولویت پایین‌تر داشتند؟ | |
| **Lesson انتخاب:** چه الگویی را در انتخاب بعدی تکرار کنیم؟ | ۱ جمله |

### اگر Lost

**تفکیک خطا — یک یا چند مورد:**

| منبع خطا | تعریف | سیگنال |
|----------|--------|---------|
| **انتخاب پروژه** | از اول نباید bid می‌شد | Score پایین، فعالیت کم، Fit ضعیف |
| **Proposal** | انتخاب درست؛ پیشنهاد ضعیف | بدون پاسخ / پاسخ سرد / Lost سریع |
| **مذاکره** | Proposal خوب؛ تبدیل نشد | پاسخ کارفرما بود؛ funnel گیر کرد |
| **عامل بیرونی** | خارج از کنترل | قیمت رقیب، انتخاب سریع دیگر، brief عوض شد |

```markdown
| فیلد | مقدار |
|------|--------|
| **خطای اصلی** | انتخاب / Proposal / مذاکره / بیرونی |
| **خطای ثانوی** | (اختیاری) |
| **Selection Score هنگام bid** | (از ثبت قبل از Proposal) |
| **آیا Score با نتیجه هم‌خوان بود؟** | بله / خیر — چرا |
| **Lesson انتخاب** | ۱ جمله actionable |
```

**ارجاع:**
- اگر **Proposal** → `proposal-generation-logic-analysis.md`
- اگر **مذاکره** → `negotiation-conversion-analysis.md`
- اگر **انتخاب** → همین فایل — بازبینی بخش ۱–۳

**قانون Lost:** Lesson جدید در Engine **نساز** — فقط ثبت تحلیل.

---

## مقایسه و الگو (دوره‌ای)

هر **۱۰** bid یا **ماهانه**:

1. Wonها — **میانگین Selection Score** و پرتکرارترین دلیل انتخاب؟
2. Lostها — چند درصد **خطای انتخاب** vs Proposal vs مذاکره؟
3. Skipهای درست — پروژه‌های Skip که بعداً «انتخاب کرده» روی دیگران → تأیید Skip؟
4. **Over-bidding** — bid با Score ≤۱۵ که Lost شد؟

**خروجی:** جدول خلاصه در پایین لاگ — پیشنهاد به `feasibility-check` فقط با تأیید کاربر + Freeze.

## ترتیب با Workflow

```
«پونیشا» / «بعدی»
  → feasibility-check (مرحله ۰)
  → **Project Selection Decision Analysis (بخش ۱–۳)** ← قبل از Proposal
  → Proposal Engine → Human Review

Skip
  → **Selection Analysis (رد + اولویت پایین‌تر)** → bids-log

Won / Lost
  → proposal-learning + Conversion + Logic
  → **Selection Analysis (بخش ۴)**
```

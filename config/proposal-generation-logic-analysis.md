# Proposal Generation Logic Analysis — تحلیل منطق ساخت Proposal

**هدف:** بعد از هر پروژه‌ای که **وارد مذاکره شد** یا **نتیجه گرفت**، بررسی کن Proposal اولیه **چرا** ساخته شد، چه **فرض‌هایی** پشت آن بود، و آیا این منطق باعث **حرکت کارفرما به مرحله بعد** شد یا نه.

**محدوده:** فقط **Learning و Analysis** — **Proposal Engine و Negotiation Engine بدون تغییر.**

| موتور | وظیفه | این فایل |
|--------|--------|----------|
| **Proposal Engine** | Risk + Insight + Simulation → بلوک ۱ | ❌ تغییر نمی‌کند |
| **Negotiation Engine** | مذاکره پس از پاسخ کارفرما | ❌ تغییر نمی‌کند |
| **Proposal Generation Logic Analysis** | یادگیری «چرا این Proposal» | ✅ فقط تحلیل |

**هدف نهایی سیستم:**

سیستم فقط یاد **نگیرد** «چه متنی بنویسد» — یاد **بگیرد** «چرا این نوع Proposal برای این نوع کارفرما و این نوع پروژه ساخته می‌شود.»

**ارتباط:**
- `proposal-learning.md` — Lessons، Human Review، تحلیل پس از نتیجه
- `negotiation-conversion-analysis.md` — funnel و مانع مذاکره
- `project-selection-decision-analysis.md` — معیار انتخاب پروژه (قبل از bid)
- `last-proposal.md` — متن و فرم آخرین پیشنهاد
- `proposal-engine.md` — **فقط مرجع**؛ منطق Engine را اینجا عوض نکن

## چه زمانی اجرا شود

| تریگر | عمل |
|--------|-----|
| «پاسخ داد» (اولین پاسخ کارفرما) | تحلیل: کدام بخش Proposal گفتگو را شروع کرد؟ |
| «پیشنهاد دادم» | **ثبت منطق ساخت** — بلافاصله بعد از Submit (فرض‌ها هنوز تازه‌اند) |
| پروژه → **Negotiation** | بررسی: آیا منطق Proposal به مرحله بعد کمک کرد؟ |

| Human Review با `[Human]` / `[Keep]` | به‌روزرسانی بخش «تصمیم‌های پشت Proposal» |

## ۱. منطق انتخاب زاویه Proposal

بعد از Submit (یا اولین پاسخ کارفرما) ثبت کن:

```markdown
| فیلد | مقدار |
|------|--------|
| ID | |
| لینک | https://ponisha.ir/project/{ID} |
| دسته پروژه | |
| **چرا این شروع انتخاب شد؟** | دغدغه / ریسک / تجربه / … — یک جمله |
| **دغدغه اصلی کارفرما (تشخیص)** | از brief — نه حدس |
| **چرا این Insight انتخاب شد؟** | یا «Insight نداد — چرا» |
| **چرا این سؤال پایانی؟** | کدام ابهام هدف گرفته شد (#12) |
| **زاویه کلی** | فنی / مدیریتی / ترکیبی |
```

**سؤالات agent (قبل از ثبت):**
- اگر کارفرما non-technical است، شروع فنی بود یا دغدغه؟
- Risk مخصوص **این** پروژه بود یا عمومی؟
- سؤال پایانی مهم‌ترین ابهام را هدف گرفت؟

## ۲. ساختار Proposal

| بُعد | ثبت |
|------|------|
| **شروع** | دغدغه / ریسک / تجربه / راه‌حل / سؤال — کدام اول آمد؟ |
| **اعتمادسازی** | روش حل / تجربه واقعی profile / ارجاع فرم / هیچ |
| **فنی vs مدیریتی** | بیشتر فنی / بیشتر مدیریتی / متعادل |
| **زبان vs سطح کارفرما** | متناسب / خیلی فنی / خیلی کلی |
| **حجم** | ~تعداد جمله؛ Scan Reading |

**سیگنال موفقیت ساختار:**
- کارفرما درباره **scope** سؤال پرسید → `[Outcome] #14` — جذب اولیه موفق
- کارفرما فقط «سلام» یا قیمت پرسید → ساختار کم‌تر اثر داشت — یادداشت کن

---

## ۳. تصمیم‌های پشت Proposal

| تصمیم | ثبت |
|--------|------|
| **قیمت** | مبلغ + جایگاه در بازه (پایین/میانه/بالا) + دلیل (#22 رقابت) |
| **زمان** | روز + واقع‌بینانه یا تهاجمی + دلیل |
| **Scope پذیرفته** | چه چیز داخل / خارج |
| **عمداً حذف شد** | چه چیز در Proposal نیامد (مثلاً پشتیبانی، جزئیات فنی) |

**منبع:** `last-proposal.md` + یادداشت Human Review + `pricing-guide.md` / `competition-guide.md`

## ۴. بررسی بعد از نتیجه

### اگر کارفرما پاسخ داد (Negotiation شروع شد)

| سؤال | پاسخ |
|------|------|
| کدام **بخش Proposal** باعث شروع گفتگو شد؟ | شروع / ریسک / insight / سؤال / قیمت فرم |
| کارفرما به چه **نقل‌قول** یا **موضوع** اشاره کرد؟ | از متن پیام |
| آیا سؤال پایانی کارفرما را به scope کشاند؟ | بله/خیر |

### اگر Won

| سؤال | پاسخ |
|------|------|
| کدام بخش **اعتماد** ایجاد کرد؟ | |
| قیمت/زمان در تصمیم چه نقشی داشت؟ | |
| چه **منطق** را در پروژه‌های مشابه تکرار کنیم؟ | یک جمله actionable |

### اگر Lost یا بی‌پاسخ نهایی

| سؤال | پاسخ |
|------|------|
| کدام بخش **احتمالاً مانع** شد؟ | شروع / اعتماد / قیمت / زمان / سؤال / insight |
| آیا منطق Proposal با brief **هم‌راستا** بود؟ | |
| آیا رقیب یا قیمت ما مانع بود؟ | از conversion analysis |

## ۵. مقایسه — Won / Lost / Lessons

برای هر تحلیل نهایی (Won یا Lost):

```
Proposal این پروژه
  ↔ ۲–۳ پروژه Won هم‌دسته (از proposal-learning / won-log)
  ↔ ۲–۳ پروژه Lost هم‌دسته
  ↔ Lessons مرتبط [Human] / [Keep] / Outcome
```

**جدول مقایسه (خلاصه):**

| بُعد | این پروژه | Won مشابه | Lost مشابه | Lesson |
|------|-----------|-----------|------------|--------|
| شروع | | | | |
| Risk | | | | |
| Insight | | | | |
| سؤال پایانی | | | | |
| قیمت (جایگاه بازه) | | | | |
| زمان | | | | |

**خروجی:** ۱–۲ **الگو** استخراج‌شده — مثلاً «شروع از دغدغه + سؤال scope در ووکامرس → پاسخ کارفرما»

**قانون:** الگو → پیشنهاد به `proposal-learning` — **نه** تغییر خودکار `proposal-engine.md`

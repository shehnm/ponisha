# بررسی ثبت پیشنهاد — Pending Bid Check

**هدف:** جلوگیری از فراموشی ثبت «پیشنهاد دادم» در `bids-log` بعد از ارسال واقعی در پونیشا.

**این فایل workflow ثبت است — نه Proposal Engine و نه Negotiation Engine.**

---

## فایل‌های مرتبط

| فایل | نقش |
|------|-----|
| `config/last-proposal.md` | آخرین Proposal تولیدشده توسط agent (منبع حقیقت برای چک) |
| `config/bids-log.md` | ثبت نهایی پس از «پیشنهاد دادم» |
| `config/proposal-learning.md` | ردیف اولیه یادگیری (همان قانون قبلی) |
| `config/project-status.md` | وضعیت‌های Submitted / Negotiation / Won / Lost |

---

## تریگر

| عبارت کاربر | عمل |
|-------------|-----|
| **«پونیشا»** / **«بعدی»** | **اول** Pending Bid Check — **بعد** (در صورت OK) جستجو + Proposal جدید |
| **«پیشنهاد دادم»** | ثبت در `bids-log` + `proposal-learning` + به‌روز `last-proposal` → Submitted |
| **«هنوز ارسال نکردم»** | بدون تغییر در `bids-log`؛ پروژه جدید شروع **نشود** |

---

## الگوریتم (اجباری — قبل از پروژه جدید)

```
۱. config/last-proposal.md را بخوان
۲. اگر خالی است یا «بدون Proposal فعال» → ادامه به پروژه جدید
۳. ID پروژه last-proposal را در bids-log جستجو کن
۴. اگر ID در bids-log نیست → توقف — پیام زیر را بده (پروژه جدید نساز)
۵. اگر ID در bids-log است → وضعیت last-proposal را با bids-log هم‌خوان کن → ادامه
```

---

## پیام توقف (اگر ثبت نشده)

> به نظر می‌رسد پیشنهاد قبلی هنوز در bids-log ثبت نشده. آیا ارسال شد؟
>
> - **«پیشنهاد دادم»** → ثبت Submitted
> - **«هنوز ارسال نکردم»** → بدون تغییر

خلاصه Proposal قبلی را در همان پیام نشان بده: ID، عنوان، مبلغ، زمان.

---

## وضعیت‌های last-proposal

| وضعیت | معنی |
|--------|------|
| **Draft** | پیش‌نویس تولید شد؛ Human Review نشده یا ناقص |
| **Ready** | نسخه نهایی آماده ارسال؛ هنوز در پونیشا submit نشده |
| **Submitted** | در `bids-log` ثبت شده |
| **Negotiation** | هم‌خوان با `bids-log` / `project-status` |
| **Won** / **Lost** | هم‌خوان با `bids-log` / `project-status` |

---

## بعد از تولید Proposal جدید

agent **باید** `config/last-proposal.md` را به‌روز کند:

- ID، عنوان، مبلغ، زمان تحویل، متن بلوک ۱
- تاریخ تولید (شمسی)
- وضعیت: **Draft** (پیش‌نویس) یا **Ready** (پس از Human Review / تأیید کاربر)

---

## ثبت با «پیشنهاد دادم»

### ۱. `bids-log.md`

ردیف جدول:

| تاریخ | ID | عنوان | مبلغ | زمان | وضعیت |

- تاریخ = امروز (شمسی) مگر کاربر تاریخ دیگری بگوید
- وضعیت = **Submitted**

بخش **متن Proposal** (زیر جدول یا در `## جزئیات Proposalها`):

```markdown
### [ID] — [عنوان]

| فیلد | مقدار |
|------|--------|
| تاریخ ثبت | … |
| مبلغ | … |
| زمان تحویل | … روز |
| وضعیت | Submitted |

**متن ارسال‌شده:**

\`\`\`text
[بلوک ۱ — متن چت پونیشا]
\`\`\`
```

### ۲. `proposal-learning.md`

ردیف اولیه (همان قانون قبلی «پیشنهاد دادم»).

### ۳. `last-proposal.md`

- وضعیت → **Submitted**
- `در bids-log` → **بله**
- `تاریخ ثبت bids-log` → تاریخ ثبت

### ۴. System Metrics

+۱ Proposal در `proposal-learning.md` (پس از Freeze).

---

## «هنوز ارسال نکردم»

- `bids-log` — **بدون تغییر**
- `last-proposal` — **بدون تغییر** (همان Draft/Ready)
- **پروژه جدید شروع نشود** در همان نوبت
- اگر کاربر بعداً گفت «بعدی» / «ردش کن» / «پروژه جدید» → می‌تواند last-proposal را نادیده بگیرد **فقط** اگر صریحاً بگوید پیشنهاد قبلی را رها کند؛ وگرنه دوباره همان چک

---

## استثنا

اگر `last-proposal` مربوط به پروژه‌ای است که در **رد شده (پیشنهاد نده)** یا **Lost** است → چک را رد کن و last-proposal را پاک/آرشیو کن.

---

## commit

بعد از ثبت «پیشنهاد دادم» یا به‌روزرسانی معنادار `last-proposal` → commit با پیام مثل: `bids-log: #749426 Submitted`

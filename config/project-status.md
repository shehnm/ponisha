# مدیریت وضعیت پروژه‌های پونیشا

**هدف:** پروژه‌هایی که عملاً از دست رفته‌اند در حالت انتظار نمانند؛ Win Rate و آمار مذاکره واقعی بماند.

**محدوده:** مدیریت وضعیت + ثبت در `proposal-learning.md` / `bids-log.md` — **نه** Proposal Engine، **نه** Negotiation Engine.

**ارتباط:** `proposal-learning.md` — تحلیل Lost؛ `bids-log.md` — وضعیت سریع per پروژه؛ `last-proposal.md` — قبل از ثبت.

---

## وضعیت‌های pre-submit (فقط `last-proposal.md`)

| وضعیت | معنی | در bids-log؟ |
|--------|------|--------------|
| **Draft** | پیش‌نویس تولید شده | خیر |
| **Ready** | آماده paste در پونیشا — **ارسال نشده** تا «پیشنهاد دادم» | خیر |

**Ready ≠ Submitted.** Pending Bid Check: اول **شواهد** (گفتگو، اسکرین، لاگ) — اگر کافی بود ثبت خودکار؛ وگرنه سؤال. **حدس ممنوع.**

---

## وضعیت‌های استاندارد

| وضعیت | معنی | در آمار فعال مذاکره؟ | در Win Rate؟ |
|--------|------|----------------------|--------------|
| **Submitted** | پیشنهاد ارسال شده؛ نتیجه مشخص نیست | خیر | خیر (هنوز باز) |
| **Waiting for client** | کارفرما هنوز فریلنسر انتخاب نکرده | خیر | خیر (هنوز باز) |
| **Negotiation** | کارفرما پاسخ داده؛ گفتگو ادامه دارد یا پس از پاسخ ما منتظر کارفرما | **بله** (تا Lost/Won) | خیر (هنوز باز) |
| **Won** | پروژه گرفته شد | خیر | **بله** (برد) |
| **Lost** | کارفرما فرد دیگری را انتخاب کرد | **خیر** | **بله** (باخت) |

### زیروضعیت‌های مجاز (یادداشت — نه جایگزین وضعیت اصلی)

| زیروضعیت | والد | معنی |
|----------|------|------|
| `waiting after our reply` | Negotiation | پاسخ کارفرما → پاسخ ما → سکوت کارفرما |
| `waiting after negotiation` | Negotiation | همان — نام مستعار در لاگ #749144 |

**قانون:** پروژه **Lost** هرگز در «نرخ پاسخ مذاکره» یا «پروژه‌های در انتظار کارفرما» محاسبه نشود.

## تشخیص Lost (باخت واقعی)

اگر در صفحه پروژه پونیشا روی پیشنهاد **فریلنسر دیگر** نوشته باشد:

> **کارفرما این پیشنهاد را انتخاب کرده است**

→ **Status = Lost** — فوراً از حالت Waiting / Negotiation خارج شود.

**نشانه‌های تکمیلی:**
- مهلت ارسال پیشنهاد به اتمام رسیده + فریلنسر دیگر انتخاب شده
- `status_code=3` در داده API (اگر در دسترس بود)

**نه Lost:**
- فقط سکوت کارفرما (هنوز Negotiation یا Waiting for client)
- کارفرما فریلنسر انتخاب نکرده

> «آیا می‌خواهید پروژه‌های قبلی را بررسی کنم و ببینم کدام کارفرما فریلنسر دیگری را انتخاب کرده است؟»

**تریگر (هرکدام زودتر اتفاق افتاد):**

## ثبت Lost در Learning

**قانون:** از **یک** باخت Lesson جدید ساخته **نشود**. فقط داده + تحلیل احتمالی. اگر الگو تکرار شد (چند باخت مشابه) → **پیشنهاد** تحلیل یا تغییر به کاربر — نه Lesson خودکار.

### اسکیما — هر پروژه Lost

```markdown
### [ID] — [عنوان]

| فیلد | مقدار |
|------|--------|
| شناسه پروژه | |
| تاریخ پیشنهاد | |
| مبلغ پیشنهادی | |
| زمان پیشنهادی | |
| متن Proposal (بلوک ۱) | |
| وضعیت نهایی | **Lost** |
| فریلنسر انتخاب‌شده | (اگر قابل مشاهده) |
| تاریخ تشخیص Lost | |
| تحلیل احتمالی دلیل باخت | (فرضی — نه Lesson) |
| Lesson ساخته شد؟ | **خیر** — مگر الگوی تکرارشونده |
```

## تریگرهای کاربر → وضعیت

| عبارت / رویداد | وضعیت جدید |
|----------------|------------|
| «پیشنهاد دادم» | Submitted |
| کارفرما هنوز انتخاب نکرده (بدون پاسخ چت) | Waiting for client |
| «پاسخ داد» / کارفرما در چت پیام داد | Negotiation |
| پاسخ ما + سکوت کارفرما | Negotiation + `waiting after our reply` |
| «بردیم» | Won |
| «باختیم» / انتخاب فریلنسر دیگر در پونیشا | Lost |
| کارفرما دوباره پیام داد پس از سکوت | Negotiation (مرحله ۲) |

## Win Rate و متریک‌ها

| متریک | فرمول / قانون |
|--------|----------------|
| Win Rate | `Won / (Won + Lost)` — فقط پروژه‌های **حل‌شده** |
| نرخ پاسخ کارفرما | فقط Submitted → پاسخ اول؛ **بدون** Lost |
| مذاکره فعال | فقط `Negotiation` — **بدون** Lost |
| System Metrics (`proposal-learning`) | Lost = +۱ نتیجه؛ **خارج** از شمارنده «منتظر» |

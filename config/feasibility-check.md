# ارزیابی قبل از پیشنهاد (اجباری)

کاربر پروژه‌ها را **با Cursor و مدل‌های AI** انجام می‌دهد. قبل از نوشتن پیشنهاد برای کارفرما، **اول به خود کاربر** جواب بده.

---

## ترتیب خروجی

### مرحله ۰ — فقط برای کاربر (نه پونیشا)

```
ارزیابی:
- قابل انجام با Cursor + AI: بله / بله با ریسک / خیر
- ریسک: کم / متوسط / بالا
- دلیل کوتاه (۱–۳ جمله)
```

**اگر «خیر» یا «ریسک بالا»:** پیشنهاد ننویس — بگو چرا، پیشنهاد بده bid نکند یا چه شرطی لازم است. مگر کاربر بگوید «باز هم پیشنهاد بده».

**اگر «بله» یا «بله با ریسک» قابل قبول:** برو مرحله ۱.

### مرحله ۱ — خروجی پونیشا

فقط **متن پیشنهاد** + **فرم پونیشا** (طبق `output-format.md`).

**ممنوع در پیشنهاد کارفرما:** هر اشاره به AI، Cursor، هوش مصنوعی.

---

## توانایی‌های تأییدشده (کاربر + Cursor)

| حوزه | وضعیت |
|------|--------|
| وردپرس / ووکامرس (سایت، فروشگاه، افزونه، بهینه) | قوی |
| HTML / CSS / JS اختصاصی | قوی |
| PHP / MySQL / پنل وب | قوی |
| Python / اتوماسیون / import انبوه | قوی |
| Odoo / ERP / ماژول | قوی (تجربه سیراف) |
| Elementor Pro اختصاصی | خوب |
| cPanel / دیباگ وردپرس / سئو تکنیکال | خوب |
| UI از مسیر HTML -> Figma (html.to.design) | خوب با محدودیت |
| nopCommerce / ASP.NET / IIS | **ریسک متوسط** — فقط اگر scope روشن باشد |

---

## ریسک بالا — معمولاً پیشنهاد نده

- طراحی **فقط** دستی Figma بدون پیاده‌سازی وب (کارفرما Figma خالص می‌خواهد)
- اپ **نیتیو** iOS/Android بدون تجربه قبلی
- بازی، Unity، سرور گیم (SAMP و …)
- سخت‌افزار، PLC، embedded
- بودجه/زمان غیرواقعی برای scope (مثلاً GTmetrix 98 + گرافیک کامل + ۲۰ صفحه در ۵M)
- پروژه‌ای که **حضور فیزیکی** یا تیم بزرگ می‌خواهد
- nopCommerce عمیق بدون دسترسی تست و scope مبهم

---

## ریسک متوسط — با شرط پیشنهاد بده

- Figma + وردپرس: UI از HTML/import، نه طراحی دستی خالص
- فروشگاه کامل با امکانات زیاد در بودجه تنگ -> زمان و قیمت واقع‌بینانه در فرم
- nopCommerce: فقط با لینک سایت + لیست تفاوت‌ها + دسترسی
- scope مبهم: قیمت اولیه + «بعد از جزئیات تنظیم می‌کنم»

---

## چک‌لیست سریع

1. stack پروژه در توان کاربر + AI هست؟
2. بودجه و زمان با scope می‌خواند؟
3. کارفرما چیز غیرقابل انجام با AI می‌خواهد؟ (Figma دستی خالص، native app، …)
4. سطح ۰ پونیشا + رقابت زیاد -> ریسک acceptance

هر «نه» جدی -> ارزیابی منفی یا ریسک بالا.

---

## به‌روزرسانی

وقتی کاربر گفت پروژه‌ای را انجام داد یا شکست خورد -> این جدول را آپدیت کن.
